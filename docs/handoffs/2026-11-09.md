## Decisions & gotchas
- **Merges:** only on the owner's "merge" for change PRs; squash with `expectedHeadSha` pinned. Read the sdd verdicts from the `checks` job log of a `pull_request_target` run of `sdd-checks.yml` whose head is the PR's head. Archive PRs merge on their own once mechanical (`autoMerge: true`), after re-running `sdd-archive.sh verify` from a clean checkout of `main` with `npm ci --ignore-scripts`.
- **Report `/ci:minutes <pr>` and model spend at each merge.** This session spent about $10.9.
- **npm 10 crashes building a new lock file** (`edgesOut`, vitest 4 peers). garmin-mtp's lock started from webusb-mtp's (ADR 0005). Use `npx npm@11 install` if a fresh lock is ever needed.
- **Never gate a commit on a piped check** (`check | tail && git commit`): the pipe's status is `tail`'s. Write the output to a file and test the exit code.
- **The classifier refused** a force-push (so merge `main` instead), and refused attaching garmin-map until the owner asked for it. Public repos clone without attaching.
- **Owner style:** short answers; ask once when something is ambiguous; merge first, then follow up rather than grow a PR. The owner accepted the defaults for all of lift-garmin-core's open questions.
- **Private → public:** garmin-map is private; garmin-mtp and webusb-mtp are public. Scan each PR's diff for the app's private material (CLAUDE.md rule).
- **The publish credential lives in one job that runs no project code** (webusb-mtp ADR 0010; CLAUDE.md). Keep that layout.
- **Neither library uses ci-recipes**; moving them onto it is the owner's call.
